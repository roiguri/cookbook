1 ש׳ · בינוניממתין לאישור
Finding 1 — RTL mirroring. cards.css positions .recipe-card__stamp with left: 12px and .recipe-card__fav with right: 12px. Physical properties do not mirror under dir="rtl", so in Hebrew the stamp lands on the visual left, away from the reading edge. This page patches both to inset-inline-start / inset-inline-end. There are no [dir="rtl"] overrides anywhere in src/styles/, so this pattern is likely repeated elsewhere and is worth a sweep.
Finding 2 — Hebrew titles use a Latin display font. recipe-card-styles.js:137 sets the title to var(--font-display) — Instrument Serif, italic. Recipe titles are Hebrew, which that font does not cover, so they fall back per-glyph and the italic is typographically meaningless in Hebrew. --font-display-he (Noto Serif Hebrew) exists in tokens.css and appears unused. Pre-existing, not caused by this feature — but every card on this new page inherits it.

Screen 3 · Stage 1

Mobile — the rail becomes a scroller

Decided rather than left open: a horizontal scroller, not a drawer. The rail has two entries at Stage 1 and only grows to a handful with user lists, so hiding it behind a drawer would cost a tap to reach the primary navigation of the page. Drawers stay for content that is genuinely secondary, as in /my-meal's ingredients panel.

Screen 7 · edge case

Tombstone — a saved recipe that was deleted

There is no unpublish, but a manager can still delete a public recipe. Because the collection entry carries its own denormalised card data, it degrades to a dismissible tombstone instead of a broken tile — a free payoff from a decision made for read performance.

What this prototype does not answer

The migration moment. A user with 40 favourites signs in after Stage 1 and sees both a מועדפים tab and a new המתכונים שלי page showing the same recipes. Needs either a one-time explanation or a decision to remove the מועדפים tab in Stage 1 rather than Stage 4.
Loading states. page-manager has an explicit spinner contract (render → showLoading → mount → hideLoading). The collection page reads the subcollection and may also run the orphan self-heal query, so it has two sources to resolve before it can hide the spinner.
Add-to-meal from the collection. The grid already supports show-add-to-meal. Whether it stays on in the collection context — and how it reads next to the lifecycle actions — is undecided.
